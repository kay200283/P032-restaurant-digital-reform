1.1 沿用 v1 已拍板决策不重复论证

业务定位

  • 纯实物记录 ＋ 期间对比，不做库存账、不涉及进货登记

录入与数据

  • 双计量全开放：整件数 × 单位容量 ＋ 拆零量(g/ml)，终值折算最小单位
  • 盘点清单快照固化：生成后档案变更不回写已建单据
  • 语音"按住说一批"（DeepSeek 封闭集合解析）为下期 P2 能力
  • is_inventory='是' 作为参与盘点的原料开关

03数据模型

新增 5 表，SQLite 沿用 P027 风格。核心关系：一个任务（inventory_tasks）展开为 N 张门店盘点单（inventory_task_stores），并固化一份盘点品清单（inventory_task_items）；库位（inventory_locations）独立于任务存在，下期盘点执行时引用。

3.1 inventory_tasks — 盘点任务主表

CREATE TABLE IF NOT EXISTS inventory_tasks (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    task_code TEXT UNIQUE NOT NULL,        -- 盘点编号 PD261018001（04 节）
    task_name TEXT NOT NULL,               -- 自动生成或特殊盘手输
    task_type TEXT NOT NULL,               -- monthly 月盘 / weekly 周盘 / special 特殊盘
    count_type TEXT NOT NULL DEFAULT 'material',  -- material 原物料 / packaging 包材耗材 / other 其他
    start_date TEXT NOT NULL,              -- 盘点开始日期 YYYY-MM-DD
    end_date TEXT NOT NULL,                -- 盘点结束日期
    ingredient_scope TEXT NOT NULL,        -- all 全部原料 / specific 指定原料
    store_scope TEXT NOT NULL,             -- all 全部门店 / specific 指定门店
    created_by INTEGER REFERENCES users(id),
    created_at TEXT DEFAULT (datetime('now','localtime')),
    updated_at TEXT DEFAULT (datetime('now','localtime'))
);

3.2 inventory_task_items — 盘点品清单（快照固化）

CREATE TABLE IF NOT EXISTS inventory_task_items (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    task_id INTEGER NOT NULL REFERENCES inventory_tasks(id) ON DELETE CASCADE,
    ingredient_id INTEGER NOT NULL REFERENCES ingredient_library(id),
    ingredient_code TEXT DEFAULT '',       -- 快照：防原料档案后续变更/删除导致清单不可读
    ingredient_name TEXT DEFAULT '',       -- 快照
    created_at TEXT DEFAULT (datetime('now','localtime')),
    UNIQUE(task_id, ingredient_id)
);
设计决策：创建时快照固化（沿用 v1 原则） 无论 all / specific，创建任务时统一落明细：all = 当日全部 status='启用' AND is_inventory='是' 原料写入清单。此后原料库增删改不影响本任务清单——门店盘的东西从创建那一刻就定死，报告口径稳定。名称/编码同步快照，原料档案被删也不产生孤儿显示。

3.3 inventory_task_stores — 门店盘点单（任务×门店展开）

CREATE TABLE IF NOT EXISTS inventory_task_stores (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    task_id INTEGER NOT NULL REFERENCES inventory_tasks(id) ON DELETE CASCADE,
    store_id INTEGER NOT NULL REFERENCES stores(id),
    count_code TEXT UNIQUE NOT NULL,     -- 门店盘点单编号 PD261018001-500715（任务编号-店编，by店独立唯一）
    status TEXT DEFAULT 'pending',         -- pending 待盘点 / submitted 已提交 / audited 已审核
    submitted_at TEXT, submitted_by INTEGER REFERENCES users(id),
    audited_at TEXT,   audited_by INTEGER REFERENCES users(id),
    created_at TEXT DEFAULT (datetime('now','localtime')),
    UNIQUE(task_id, store_id)              -- 复刻 product_barcode_stores 展开表模式
);
  • 创建任务时按门店范围立即展开：all = 全部启用门店；specific = 勾选门店。
  • 该表即下期门店执行端的工作队列：门店登录只看到自己 pending/submitted 的任务。
  • 门店盘点单独立编号（10-18 拍板）：任务编号-店编（PD261018001-500715），创建展开时自动落库，UNIQUE 保证 by 店唯一、数据不混。

3.4 inventory_locations — 库位表

CREATE TABLE IF NOT EXISTS inventory_locations (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    location_code TEXT UNIQUE NOT NULL,    -- 库位编号 500715-001（04 节）
    store_id INTEGER NOT NULL REFERENCES stores(id),
    area_name TEXT NOT NULL,               -- 区域名称（单行文本）
    status TEXT DEFAULT '启用',            -- 启用/停用（预留，下期盘点落位用）
    created_by INTEGER REFERENCES users(id),
    created_at TEXT DEFAULT (datetime('now','localtime')),
    updated_at TEXT DEFAULT (datetime('now','localtime')),
    UNIQUE(store_id, area_name)            -- 同店区域名称防重
);

3.5 inventory_used_codes — 编号墓碑（删除不复用）

CREATE TABLE IF NOT EXISTS inventory_used_codes (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    scope TEXT NOT NULL,                   -- task 任务编号 / location 库位序号
    code TEXT NOT NULL,                    -- 完整编号或 店编+序号
    created_at TEXT DEFAULT (datetime('now','localtime'))
);
CREATE INDEX idx_iuc ON inventory_used_codes(scope, code);
复刻先例 与 P029 道具/广告编码治理同款方案（display_used_codes 墓碑表）：删除时登记，生成时"现存最大值 vs 墓碑最大值"取大 ＋1。业务编码永不复用。

04编号规则

两类编号均为创建时服务端自动生成、全局唯一、删除永不复用。生成模式复刻现有 generate_ingredient_code（前缀＋日期＋当日流水取最大 ＋1）。

4.1 盘点任务编号

PD + YYMMDD + 3位当日流水　→　例：PD261018001、PD261018002 …
  • PD＝盘点（PanDian）业务前缀，与现有 ING（原料）/ SP（半成品）风格一致，5＋3＝10 位，列表/导出可读性好。
  • 流水按当日独立：同日第 1 单 001、第 2 单 002；跨日重新从 001 起（日期段不同天然不冲突）。
  • 唯一约束 task_code UNIQUE ＋ 生成时事务内取号，并发安全。

4.2 库位编号

店铺编号 + "-" + 3位店内流水　→　例：500715-001、500715-002 …；500716-001（独立序列）
  • 按用户要求"店铺编号+001 开始排序"：每店独立流水，跨店编号天然不混（店编唯一）。
  • 序号取号范围 = 该店现存库位 ∪ 该店墓碑序号，最大值 ＋1 → 删除的序号永不复用。
  • UNIQUE(location_code) 兜底唯一。

4.4 门店盘点单编号（by 店独立）

门店盘点单编号 = 任务编号 + "-" + 门店编码　→　例：PD261018001-500715、PD261018001-500716 …
  • 任务展开派发时自动生成并落库（inventory_task_stores.count_code，UNIQUE），后续盘点录入、审核、报告全部按此编号定位，by 店数据永不混。
  • 派生编号不进墓碑（随任务删除一并消失；任务编号墓碑已保证同号不复用，派生号天然唯一）。

4.3 墓碑机制流程两类编号通用

① 创建取号：MAX(现存流水, MAX(墓碑流水)) + 1
→
② 写入业务表（UNIQUE 兜底）
→
③ 删除业务行 → 编号写入 inventory_used_codes
→
④ 再创建取号跳过墓碑值，永不复用

示例：500715 建过 3 个库位后全删 → 墓碑记 001/002/003 → 再建新库位得到 500715-004。

06库位管理（/inventory_location）

门店自管储存位置：一店多库位（常温货架/冷藏柜/冷冻库…），下期盘点按库位落位。角色：管理员、采购料理、总部运营、区域管理、门店全开；TP 不可见。门店与区域管理做店别内容隔离。

6.1 店别数据隔离矩阵复用 bind_store_code / bind_region

角色数据可见范围创建时门店选择实现
管理员/采购料理/总部运营全部 26 店库位门店下拉全量可选无附加过滤
门店仅本店库位锁定为本店（只读展示，不可改）session bind_store_code → 强制 WHERE store_id=本店；后端强制，前端同时锁定
大区管理大区内门店库位下拉仅大区门店session bind_region → WHERE stores.region=bind_region
现状依赖与降级策略 stores.region 当前 26 家店全部为空，系统也无真实大区管理账号。方案按 region 字段隔离实现；region 未维护期间，大区管理登录将看到空列表并提示"所属大区未配置门店"，不会误见全量数据。大区归属数据的维护（stores.region 赋值）需要单独安排（待确认）。

6.2 创建与列表

  • 创建：选择门店（按 6.1 矩阵受限）＋ 区域名称（单行文本，同店防重校验）。编号自动生成 店编-001 起流水，成功后 toast 展示新编号。
  • 列表：库位编号 / 门店 / 区域名称 / 状态 / 创建人 / 创建时间；模糊搜索（编号+区域名称）、门店筛选（管理员侧）、导出。
  • 修改：区域名称可改（防重校验）；门店与编号不可改（编号含店编，挪店＝编号失效）。
  • 删除：二次确认 → 入墓碑，序号永不复用；下期若已被盘点明细引用则拦截删除（本期预留校验位）。
  • 门店手机场景：建库位是门店高频操作——手机端单列卡片＋右下角悬浮"＋"大按钮（见 07 节）。

07手机端卡片式适配

手机端整体采用卡片式呈现，交互基准复刻罗森批发系统「废止换品工作台·批量换品」已验证的模式：rp-card 三段卡片（头/体/脚）＋ 桌面/手机双渲染 ＋ 760px 断点切换 ＋ 状态徽章。

7.1 双布局机制与批量换品同构

  • 同一份数据两套渲染：dt-only（PC 表格）与 m-only（手机卡片）互斥显示，断点 @media (max-width:760px) 切换——列表数据只需一次拉取。
  • 卡片结构：头＝编号＋状态徽章；体＝键值行（名称/类型/日期/进度）；脚＝操作按钮横排。
  • 触控规范：可点区域 ≥ 44px；按钮整块可点；弹窗手机端全屏化（100dvh）；筛选栏折叠为"筛选"按钮展开面板。
